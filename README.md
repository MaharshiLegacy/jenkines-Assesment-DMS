# Document Management System (Spring Boot monolith)

Single deployable Spring Boot 3 / Java 17 application: upload, store, search, view, download, update,
delete documents (PDF, Word, Excel, PowerPoint, images) with JWT authentication, role-based access, and owner-only document access.

```
mvn spring-boot:run          # http://localhost:8080
mvn test                     # MockMvc integration tests (security, access control, validation, domains)
```

Demo accounts (seeded, change via `app.seed.*`): `admin / Admin@123` (ADMIN), `user / User@123` (USER). Authentication is JWT (see below).

## Architecture

```
controller  -> thin HTTP layer (validation, mapping, headers)
service     -> business rules + ALL document authorization (DocumentService.authorize)
repository  -> Spring Data JPA
security    -> SecurityConfig, JWT (JwtConfig/JwtService/JwtUserConverter), DomainRestrictionFilter
exception   -> ApiException, GlobalExceptionHandler, ApiErrorWriter (JSON errors for filters too)
```

## Database

| Table | Purpose | Key constraints |
|---|---|---|
| `users` | accounts, BCrypt hash, role (`USER`/`ADMIN`), enabled | unique username, unique email |
| `documents` | file details: title, description, original/stored filename, content type, size, SHA-256, owner, timestamps | `owner_id` FK, unique `stored_filename`, indexes on owner + title |
| `document_metadata` | free-form key/value tags per document | unique (`document_id`, `meta_key`) |

Schema is generated by Hibernate (`ddl-auto=update`) for the exercise; use Flyway/Liquibase in production.

## Authentication (JWT)

1. An **admin creates users** (`POST /api/admin/users`); there is no self-registration.
2. A user calls `POST /api/auth/login` with username + password and receives a signed JWT (HS256, 60 min by default).
3. Every other call sends `Authorization: Bearer <token>`.

```
POST /api/auth/login  {"username":"user","password":"User@123"}
-> {"accessToken":"eyJ...","tokenType":"Bearer","expiresInSeconds":3600,"username":"user","role":"USER"}
```

* Token carries only `sub` (user id), `iss`, `iat`, `exp`. **The role is never trusted from the token**:
  `JwtUserConverter` loads the user from the DB on each request, so a disabled/deleted user or a changed role
  takes effect immediately even though the token itself is still unexpired.
* Signature, expiry and issuer are verified by Spring's `JwtDecoder` (Nimbus). Tampered or expired tokens -> 401.
* Passwords are BCrypt-hashed; login failures return one generic message (no account enumeration).
* **Set `APP_JWT_SECRET`** (>= 32 bytes) in any real environment; the app logs a warning while the dev default is in use.
* Trade-off: stateless JWTs can't be revoked individually; mitigated by short expiry + the per-request enabled check.
  Add refresh tokens / a denylist if you need logout-everywhere.

## REST API

| Method & path | Who | Notes |
|---|---|---|
| `POST /api/auth/login` | public | returns JWT |
| `GET /api/auth/me` | any user | current user |
| `POST /api/documents` | any user | multipart: `file`, `title?`, `description?`, `metadata?` (JSON object string) |
| `GET /api/documents?q=&page=&size=` | any user | **only documents you uploaded** (admin: all); search title/filename/metadata |
| `GET /api/documents/{id}` | owner/admin | details |
| `GET /api/documents/{id}/view` | owner/admin | inline preview |
| `GET /api/documents/{id}/download` | owner/admin | attachment |
| `PUT /api/documents/{id}` | owner/admin | JSON: title, description, metadata (replaces set) |
| `POST /api/documents/{id}/file` | owner/admin | replace the file content |
| `DELETE /api/documents/{id}` | owner/admin | removes row + metadata + file on disk |
| `GET/POST /api/admin/users`, `PATCH/DELETE /api/admin/users/{id}` | ADMIN | create users, set role, enable/disable, reset password |
| `GET /api/admin/documents` | ADMIN | all documents |

```bash
TOKEN=$(curl -s -H 'Content-Type: application/json' -d '{"username":"admin","password":"Admin@123"}' \
        localhost:8080/api/auth/login | sed 's/.*"accessToken":"\([^"]*\)".*/\1/')

# admin creates a user
curl -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -d '{"username":"bob","email":"bob@acme.com","password":"Bob@12345","role":"USER"}' localhost:8080/api/admin/users

# bob logs in and uploads
BOB=$(curl -s -H 'Content-Type: application/json' -d '{"username":"bob","password":"Bob@12345"}' \
      localhost:8080/api/auth/login | sed 's/.*"accessToken":"\([^"]*\)".*/\1/')
curl -H "Authorization: Bearer $BOB" -F file=@report.pdf -F title="Q3 Report" -F 'metadata={"dept":"finance"}' localhost:8080/api/documents
curl -H "Authorization: Bearer $BOB" -OJ localhost:8080/api/documents/1/download
```

## Access control

| | list / view / download | update / replace / delete | manage users |
|---|---|---|---|
| ADMIN | all documents | all documents | yes |
| USER | only documents they uploaded | only documents they uploaded | no (403) |
| USER accessing someone else's document | 403 | 403 | n/a |

* Document rules live in `DocumentService.authorize`, so a new controller cannot accidentally bypass them.
* Admin URLs are protected twice: URL rule (`/api/admin/**` -> `ROLE_ADMIN`) and `@PreAuthorize`.
* Deny by default: any URL not explicitly matched is rejected; the only public endpoint is `POST /api/auth/login`.

## Domain restriction

`DomainRestrictionFilter` runs **before authentication**:

* `app.security.allowed-hosts`: domains through which any `/api/**` call may arrive.
* `app.security.admin-hosts`: stricter list for `/api/admin/**` (e.g. only an internal/VPN domain).
* `*.example.com` wildcards supported; empty list = deny everything (fail-closed).
* `app.security.allowed-origins`: browser origins allowed by CORS.

The `Host` header is client-controlled, so in production also enforce the allow-list at the reverse proxy / API gateway,
and only enable `server.forward-headers-strategy=framework` behind a proxy that overwrites `X-Forwarded-*`.

## File handling

* Allowed: pdf, doc, docx, xls, xlsx, ppt, pptx, png, jpg/jpeg, gif (SVG and macro formats deliberately excluded).
* Three checks: extension whitelist, magic-number check, server-chosen Content-Type (client header ignored).
* Stored under random UUID names (no path traversal, no collisions); SHA-256 recorded.
* Size limit 25 MB (`spring.servlet.multipart.*`).
* Files are written and deleted via transaction callbacks: no orphan files after a rolled-back DB write, and a file is only removed after the DB delete commits.
* Downloads send `nosniff`, `Cache-Control: no-store` and a safe `Content-Disposition`.

## Error handling (uniform JSON: timestamp, status, error, message, path, details)

| Situation | Status |
|---|---|
| No/invalid/expired token, bad login, disabled user | 401 |
| Wrong role, someone else's document, unapproved domain | 403 |
| Document/user/stored file not found | 404 |
| Disallowed file type | 415 |
| Content does not match extension, missing file part, bad JSON, validation failure | 400 |
| File too large | 413 |
| Duplicate username/email, deleting a user who owns documents | 409 |
| Anything unexpected (details logged, never leaked) | 500 |

## Trade-offs and what I would add next

* Refresh tokens or an external IdP (OIDC) if you need longer sessions / SSO; the resource-server setup stays the same.
* Document sharing between users (a permissions table) can be added back if the requirement grows.
* Local-disk storage -> S3/MinIO behind `FileStorageService`; add antivirus scanning (ClamAV) and deep content validation (Apache Tika) for Office files.
* Versioning (keep old file versions), audit table instead of log lines, rate limiting, Flyway migrations, PostgreSQL.
* A 403 (rather than 404) is returned for existing-but-forbidden documents; switch to 404 if ID enumeration is a concern.
